File ingestion pipeline

End-to-end trace of how browser uploads become PostgreSQL rows and Parquet files in data_lake/ — with real function names, routes, and storage targets.

Related pages. Data model (schema) · REST API (upload endpoints).

Terminology

TermMeaning in CellSeer
LoaderA BaseTestTypeLoader subclass registered in backend/loaders/registry.py (MetadataLoader, CyclingFileLoader). Resolves by file extension and optional fileType hint.
DatasetNamed time-series blob for one cell — e.g. cycling, discharge_dqdv, discharge_dvdq. Stored as LZ4-compressed Parquet; indexed in the dataset PostgreSQL table via storage_uri.
cell-record-indexLightweight project-wide cell list from GET /api/cell-record-index — metadata columns plus a datasets[] summary per cell (no curve arrays).
ReadinessProject gate from GET /api/projects/{id}/readiness. canEnterDashboard is true only when at least one cell exists and at least one cell has a cycling dataset.
upload_taskEphemeral progress row (queued → processing → done | error) polled by the frontend every ~700 ms. item_count is >1 for batch uploads; message holds JSON result on success or the exception string on failure.
ingest_logAudit trail written after successful cycling ingest — one row per source file, keyed on project_id + cell_id, with detected cycler, confidence, and file_order (for multi-file continuation tests).
id_noNumeric link key between metadata rows and cycling filenames. Chosen from the metadata spreadsheet; cycling files are matched by filename heuristic or explicit per-cell attach. Not unique per project — routing always uses cell_id; id_no is purely a matching hint. If a collision is detected at ingest time the incoming cell's id_no is set to None.

Accepted file types

fileTypeLoader classExtensionsWhat it creates
metadata MetadataLoader .csv, .xlsx, .xls One cell row per valid spreadsheet row (metadata only — no Parquet yet)
cycling CyclingFileLoader .xlsx, .xls, .csv, .mpt, .mpr Parquet under data_lake/ + dataset rows (+ derived dQ/dV / dV/dQ datasets when differentiation succeeds). Accepts Neware, BioLogic, Arbin, and other Excel/CSV cycler exports.

Loader manifest: GET /api/upload/loaders → test_type_manifest() in backend/loaders/registry.py.

Three upload entry paths

PathHTTP routeFrontend triggerWhen used
Single file POST /api/upload useFileUpload.uploadWithOptions() → uploadFile() One metadata workbook or one cycling file. A dedup guard returns the existing task_id (status already_processing) if the same filename was already queued or processing in the same project within the last 20 minutes.
Batch POST /api/upload/batch useFileUpload.uploadManyWithOptions() → uploadFiles() Multiple cycling files in one background task (Project detail "Cycling data" tile, multiple input). All files must resolve to the same FILE_TYPE. Files are processed sequentially; each file's 0–100 local progress is mapped to its proportional slice of the overall 0–100 range. Final message JSON is capped at the first 20 result entries.
Per-cell attach POST /api/cells/{cell_id}/files/{test_type} useCellTestFileAttach.attach() → uploadCellTestFile() Attach cycling data to a known cell_id (expanded row in CellMetadataCard or CellDetailPanel). Only test_type=cycling is supported today. Validates the cell exists in PostgreSQL before dispatching. Passes cellId and idNo in ingest_options to bypass the filename heuristic.

All three paths share the same background worker pattern: insert upload_task, then call loader.ingest() via _run_upload or _run_upload_batch in routers/upload.py. Background tasks run in FastAPI's background task pool (same process, separate thread); each progress update opens its own PostgreSQL connection via _upload_db() (pooled psycopg2 adapter).

Where data lands

Parquet data lake

Path template from dataset_store.dataset_relpath():

{CELLSEER_DATA_LAKE_DIR}/{safe_project_id}/{safe_cell_id}/{safe_dataset_name}.parquet

Each path segment is sanitized to [A-Za-z0-9._-] (other characters replaced with _). Default root: data_lake/ at repo root (config.DATA_LAKE_DIR, override with CELLSEER_DATA_LAKE_DIR).

Example after ingesting cell B01_NMC811_R03 in project abc123:

  • data_lake/abc123/B01_NMC811_R03/cycling.parquet
  • data_lake/abc123/B01_NMC811_R03/discharge_dqdv.parquet
  • data_lake/abc123/B01_NMC811_R03/discharge_dvdq.parquet
  • …and charge-direction variants when differentiation succeeds

Post-ingest: how dashboards see new data

Ingest does not push to the browser. After upload_task.status = done:

  1. ProjectDetailPage refreshes fetchProjectReadiness and fetchCellRecordIndex.
  2. Inside the dashboard, DataRefreshContext.triggerDataRefresh() bumps dataVersion, invalidating React Query keys in useCellData.ts.
  3. GET /api/cell-record-index reads cell + dataset tables; heavy endpoints (/api/rate-performance) read Parquet via read_dataset_parquet().

Alternate ingest: DIGIBAT sync

Not covered step-by-step here — see the dedicated DIGIBAT sync deep dive. That path (backend/digibat/sync_service.py) eventually calls the same ingest_cycling_file / upsert_cell stack and lands in the same data_lake/ layout. It also populates dataset.source_file_id, source_version, and source_system fields that the browser upload path leaves null.
