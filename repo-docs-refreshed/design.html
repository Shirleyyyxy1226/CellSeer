User guide

Design language

Visual and interaction conventions — illustrated with real screens.

Principles

1 · Campaign overview first

The unit of analysis is the campaign, not the cell. The home page and Master Plot answer oversight questions — how many cells, which conditions, what failed — before you drill into GCD or differential views.

2 · Overview → inspect → drill

Master Plot summary → Inspector → GCD / dQ/dV / rate tabs. Hierarchy tree drives all views.

3 · Clear about data requirements

Metrics needing more context (e.g. retention without protocol) show a lock — never misleading numbers.

4 · Every view is shareable

Tab and filter state in the URL (?tab=, mpView, etc.). Same link = same view.

5 · Cycling-first scope

CellSeer centres on galvanostatic cycling records — the six dashboard tabs and Master Plot metrics are built around capacity, efficiency, and differential voltage curves from coin-cell cycling tests.

Who it is for

Formative research with DIGIBAT practitioners produced two behavioural segments (not job titles — one person can be both):

  • S1 — materials scientist / PhD researcher asks “how do conditions compare, and why?” Needs campaign-level comparison and per-cell mechanism views without writing scripts.
  • S2 — laboratory manager / PI asks “is the campaign complete — did every cell cycle successfully?” Needs a whole-campaign readiness view at a glance.

Views

Six tabs from one strip. Tree selection re-queries the active view.

Visual language

Colour — identity vs magnitude

Chemistry hues — DJB2 hash of cathode (+ separator/spacer offsets). Same name → same hue. Hue = identity.

cathodeHue = hash01("cathode:" + normKey(cathode)) × 360°. Conditions sharing a cathode get a separator offset (±22°) and spacer offset (±8°). Replicates share the condition hue; per-cell lightness (38–62%) and dash/symbol distinguish them within a cohort.

Metric ramps — heatmap/ranking tiles. Default red–yellow–green (not CVD-safe); viridis/cividis in toolbar.

Cycle colours — blue ramp (early = light, late = dark). Single-cell: cycleColor(t); multi-cell: cellCycleColor(hex, t).

Typography — mono micro-labels

Mono uppercase labels for counts, units, column headers (text-[11px] tracking-wider). Numbered stages (01 ·) in tree headers and stat lines.

Surfaces and density

Calm canvas: card panels, 1 px borders, small radii. Density from typography (11–14 px), not nested boxes. Destructive actions: hover-reveal + confirm.

Provenance badges

Mono chips for data source. DIGIBAT = robot-lab sync; future: UPLOAD API

Interaction patterns

  • Inspector panels (~300 px): sparkline, key stats, drill-down buttons.
  • Protocol-locked metrics show a lock + plain-language reason, never a misleading number.
  • Empty states explain what to do next (import data, select a hierarchy node).
  • Tabs are URL state via ?tab=; Master Plot also uses mpView, mpMetric, mpRamp.
  • Direction toggle inside the chart card header (Rate Performance, dQ/dV, dV/dQ).
  • 3D render guard: >200 estimated traces prompts confirmation before WebGL mount.
  • Pin conditions on heatmap/ranking rows for cross-view comparison.

Accessibility baseline

  • Tab strips use role="tablist" / role="tab" / aria-selected.
  • Icon-only buttons always carry aria-label including the object name ("Delete project X").
  • Heatmap cells carry value text, not colour alone.
  • Colour is never the sole channel for critical information — shape, label, or position always co-encodes the same fact.
  • An optional maximizeContrast mode (chart appearance popover) applies an Okabe–Ito palette via buildCellEncodings.
