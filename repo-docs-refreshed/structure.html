Backend routers

Router modules under backend/routers/ own slices of /api/*:

  • analysis.py — health, hierarchy, hierarchy-order
  • cells/ — cell index, cell records, rate performance, differential, mutations (split subpackage)
  • annotations.py — notes and tags
  • upload.py — file upload, loaders manifest, attach test files
  • projects.py — project CRUD, readiness
  • digibat.py — collections, sync, status
  • protocols.py — protocol template CRUD
  • master_plot.py — overview and peak-shift aggregate endpoints

Key library files

Notable files under frontend/src/lib/ that are referenced across features:

  • Colour helpers — Colour system (cellColorScheme.ts, cycleColormap.ts)
  • lib/plot/differentialUtils.ts — cellColor and cycleFadeColor re-exported by charts/style.ts
  • lib/api/ — typed fetch wrappers for all backend endpoints
  • lib/plot/exportUtils.ts — CSV/image export helpers

Extension points

In brief:

  • New overview metric — frontend/src/features/masterPlot/overview/metrics.ts
  • New plot type — add builder in frontend/src/charts/plotting/ + dashboard in features/
  • New cycler format — backend/loaders/ or backend/compute/readers/cycling/
  • New API endpoint — add router module or extend existing router, register in api.py
Package naming — two Python trees share the name cellseer:
  • cellseer/ at repo root — pip-installable plotting library (pip install -e cellseer)
  • backend/compute/ — internal ingest/analysis package used only by the server
They are separate packages with different roles. The TypeScript figure builders live in frontend/src/charts/ and are imported via the Vite alias @/charts. See the naming table below.
