Architecture

How the browser, API, storage, external services, and plotting libraries connect. Deep dives: Ingestion pipeline (data path) · Dashboard & plot guide (UI).

Positioning

CellSeer is an independent visualisation layer above laboratory data management (DIGIBAT datalab, shared drives, cycler exports). It maintains its own working store (PostgreSQL + Parquet) and does not replace the source of truth in the datalab or on instrument PCs. Two first-class ingestion paths: direct upload (metadata spreadsheet + cycler files) and optional DIGIBAT API sync. The tool runs with or without an institutional datalab.

Auth layer

When CELLSEER_API_TOKEN is set, backend/auth.py requires Authorization: Bearer … on all /api/* paths except /api/health. The SPA captures an initial ?token= from the URL into localStorage via frontend/src/lib/api/authToken.ts and attaches it on every fetch through fetchInterceptor.ts.

Caching strategy

  • TanStack Query v5 — client-side cache for index, rate-performance, overview, cell records; tab-gated fetches avoid loading multi-MB payloads unnecessarily.
  • Server-side — cycle-summary cache and parallel Parquet reads in routers/cells/; overview reuses the same cell loader as rate-performance.
  • orjson + gzip — large JSON responses serialised and compressed in production.

Frontend rendering patterns

  • Colour — Colour system
  • ChartLegend — inside ResizableChartCard callback, not floating
  • DirectionToggle — inside chart card header
  • GCD rate panel — full RatePerformancePlot, not bespoke mini-chart
  • 3D camera — cameraEye + cameraSeq → uirevision forces reapply
  • Resize handle — render prop into Surface3dPlot plot area
  • Wheel isolation — {passive: false} on 3D canvas
