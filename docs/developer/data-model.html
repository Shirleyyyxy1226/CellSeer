User guide

Data model

PostgreSQL metadata + Parquet time series in data_lake/. Schema: backend/project_scope.py:ensure_project_schema() (11 tables).

Entity relationships

All child rows have project_id (cascade delete). cell_id = routing key; id_no = display only.

Terminology

TermMeaning
projectTop-level tenant boundary. All other tables reference project.id.
cell_idPrimary key string for a physical cell (e.g. recipe + repeat). Used for API routing and dataset joins.
id_noInteger label matching cycler filename prefix. Not unique per project — routing always uses cell_id.
capacity_basisWhich electrode's active mass normalises specific capacity (cathode | anode; NULL = infer at read time).
custom_metaJSON map on cell for spreadsheet/source fields that have no dedicated column (dynamic metadata ingest).
dataset.nameLogical time-series slot per cell (cycling, dqdv, dvdq, eis, …). Unique with (project_id, cell_id, name).
storage_uriRelative or absolute path to the Parquet payload; resolved by backend/dataset_store.py.
storage_kindStorage backend for a dataset row — currently always local; schema allows future values such as s3.
deleted_atSoft-delete tombstone on cell, dataset, and digibat_file_map. NULL means active.
protocol_templateReusable segment list (segments_json). Builtins (is_builtin = 1) are seeded per project and read-only.
protocol_segmentsInline JSON on cell (and mirrored in dataset.meta) after a template is applied or edited — not a FK to protocol_template. Each segment: { cycleStart, cycleEnd, cRate, name? }.
source_file_idDIGIBAT file identifier; joins digibat_file_map to dataset by value, not foreign key.
checksum_sha256SHA-256 of the raw Parquet bytes, computed on write by dataset_store.py. Supports idempotent DIGIBAT re-sync.
confidenceFloat 0.0–1.0 on ingest_log — cycler-detection confidence score from the format-detection step.

PostgreSQL schema

Canonical definition: backend/project_scope.py:ensure_project_schema(). The schema is applied at startup against the PostgreSQL database configured via CELLSEER_DATABASE_URL (exposed in code as config.DATABASE_URL). Column types use PostgreSQL-native types: BIGSERIAL for auto-increment PKs, TIMESTAMPTZ for all timestamp columns, TEXT for strings, INTEGER / REAL for numerics.

Table count. The schema defines 11 tables.

Cell identity

  • cell_id — stable string identifier (often encodes build recipe + repeat); composite primary key with project_id
  • id_no — integer label matching cycler filename prefix; not unique per project (routing uses cell_id). If an incoming cell's id_no would collide with an existing cell in the same project, it is set to NULL during metadata ingest.

Parquet data lake

Design note. The split between PostgreSQL metadata (cell, dataset) and Parquet payloads under data_lake/ was informed by Imperial DataLab's model of catalogue records pointing at file-backed datasets, with provenance fields carried on ingest. Browser uploads and DIGIBAT sync both converge on this layout. See Acknowledgments for the full credit statement.
  • Directory: data_lake/ (gitignored; override with CELLSEER_DATA_LAKE_DIR)
  • Access: backend/dataset_store.py resolves storage_uri paths and reads/writes Parquet
  • Path pattern: {project_seg}/{cell_seg}/{dataset_seg}.parquet where each segment is sanitized to [A-Za-z0-9._-]
  • Written via Polars LazyFrame.collect().write_parquet() with lz4 compression; atomically renamed from a .tmp file
  • Read back via polars.read_parquet(); no fixed schema enforced at the storage layer — schema is dataset-name-dependent
  • storage_kind on dataset rows is currently always local; schema allows future values such as s3
  • Checksums (checksum_sha256) are computed on raw bytes at write time and support idempotent DIGIBAT re-sync

Soft deletes

Both cell and dataset use deleted_at tombstones instead of hard deletes during DIGIBAT sync. digibat_file_map also carries a deleted_at column. Purge via CLI --purge flag on the sync script after the applicable retention period.
