Master Plot metrics pipeline

End-to-end trace of how the Master Plot overview tab turns rate-performance data into per-cell scalars, condition aggregates, and the metric-driven views. Per-cell overview scalars always come from GET /api/master-plot/overview (Python build_overview) → summariesFromOverview; the full per-cycle rate-performance payload is fetched lazily and scoped to active filters only when Trajectories, Inspector, or parallel coordinates need series data. The metric selector exposes exactly six metrics: peak capacity, peak specific capacity, Coulombic efficiency, cycles completed, capacity retention, and dQ/dV peak shift.

Related pages. Computation report (formulas) · Dashboard & plot guide (UI wiring) · Protocol attachment (protocol gating).

Orchestrator: data fetch

ProjectOverviewDashboard.tsx is the single orchestrator for the Master Plot tab (?tab=particle-master in Index.tsx). Per-cell scalars always come from the overview endpoint; there is no cell-count switch and no in-browser summariseCell.

const overviewQuery = useMasterPlotOverviewQuery({ enabled: true });
const rateQuery = useRatePerformanceQuery({
  enabled: view === 'trajectories' || inspectedId != null,
  scope: { cathode, separator, spacer },
});
FetchWhenEndpoint / functionPurpose
Overview (always) On tab load useMasterPlotOverviewQuery() → GET /api/master-plot/overview → summariesFromOverview() Per-cell scalars and condition category map for heatmap, ranking, KPIs, protocol gate
Per-cycle (lazy) Trajectories view open, Inspector open, or parallel coords needs series useRatePerformanceQuery({ scope }) — scoped to active cathode/separator/spacer filters capacitySeries / ceSeries grafted by cellId; condition views still use the project-wide overview
Peak shift (lazy) Metric dqdv-peak-shift selected useMasterPlotPeakShiftQuery() → GET /api/master-plot/peak-shift Protocol-gated metric; endpoint reserved for future segment-aware peak tracking

Condition views always consume the project-wide overview aggregate — never the scoped per-cycle payload — so opening Trajectories does not drop unseen conditions from heatmap/ranking.

Metric registry

All metrics are defined in METRICS[] in overview/metrics.ts. The score column is what drives colour-scale placement; it may differ from the raw value for diverging metrics.

Metric idCellSummary fieldUnitRequires protocolScore / directionNotes
capacity-rawpeakCapacityRawmAhNo Raw value; higher = better max() over positive finite per-cycle dischargeCapacityMah. Format: ≥10 → toFixed(0), else toFixed(2).
capacity-specpeakCapacitySpecmAh/gNo (needs cathode mass) Raw value; higher = better max() over positive finite per-cycle specificCapacityMahG. Null when cathode mass unavailable. Format: toFixed(0).
cemedianCE%Yes −|v − 100|; diverging, target = 100% Protocol-gated; UI shows lock + "needs a protocol" without segments, "Coming soon" once attached
cyclescycleCount(count)No Raw value; higher = better Count of finite, >0 entries in capacitySeries (spec series preferred, else raw). Returns null if count = 0. Format: Math.round(v).toString().
retentionretention%Yes Raw value; higher = better Protocol-gated; UI shows lock + "needs a protocol" without segments, "Coming soon" once attached
dqdv-peak-shiftpeakShiftMvmVYes −|v|; diverging, target = 0 (stable peak = best) Protocol-gated; requires discharge_dqdv dataset. Lazy fetch when selected. UI shows lock → "Coming soon". Format: +v.toFixed(0) (sign always shown).

Capacity basis fallback

If the specificCapacityMahG series is non-empty, it is used as capacitySeries (mAh/g) and recorded as capacityBasis='mAh/g'; otherwise dischargeCapacityMah is used (mAh, basis 'mAh'). The peak-capacity and cycles metrics, plus the inspector sparkline and trajectories, all read this same series (per-cycle path) or the server scalar (overview path).

Protocol gate

The three requiresProtocol: true metrics (Coulombic efficiency, capacity retention, and dQ/dV peak shift) are protocol-gated in the UI. When no cell in the project has a protocol (summaries.every(c => !c.hasProtocol), using per-cell hasProtocol from the overview), the metric shows a lock + "needs a protocol"; once a protocol is attached, it shows "Coming soon". The overview response also carries project-level protocolCellCount for API consumers; the dashboard gate uses per-cell hasProtocol.
