Overview

Campaign visualisation and analysis for high-throughput coin-cell testing — linking cycling data to metadata through a React web app and FastAPI backend.

What it does

  • Hierarchy tree — filter by metadata
  • Master Plot — heatmap, ranking, trajectories, parallel coords
  • Per-cell plots — GCD, dQ/dV 3D, dV/dQ 3D, rate performance
  • Ingest — upload (Neware, BioLogic, Arbin) or DIGIBAT sync
  • Protocols — cycle-range / C-rate segments
  • Annotations — notes and tags per cell

Three layers

LayerTechnologyRole
Frontend React 18, TypeScript, Vite, TanStack Query, Plotly, Recharts, shadcn/ui (Radix UI + Tailwind CSS) SPA dashboards, shared selection/filter state, REST client
Backend FastAPI, PostgreSQL, Parquet data lake (Polars + Pandas), orjson REST API, ingest, caching, DIGIBAT sync, serves built SPA in production
@/charts TypeScript (framework-free) Plotly figure builders under frontend/src/charts/; unit-testable without a browser

Colour system

Deterministic DJB2-hash cell colours and blue cycle ramp — see Colour system.

Data flow (summary)

  1. Ingest — upload/DIGIBAT → cell + dataset rows; time series → Parquet in data_lake/
  2. Index — GET /api/cell-record-index (lightweight metadata for tree/filters)
  3. Bulk summaries — /api/rate-performance (lazy on Rate tab); /api/master-plot/overview (scalars — metrics)
  4. On-demand curves — /api/cell-record/{id} + differential endpoints
  5. Rendering — @/charts → PlotlyChart

Projects and routing

Multi-project: home → detail → /projects/:projectId/dashboard. Legacy alias /dashboard — Dashboard guide.
